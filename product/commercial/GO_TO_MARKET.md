## 1. GTM 总原则

1. **从任务密度出发**，不从 Product Hunt 掌声出发。  
2. **垂直岗位与真实页面**优先于泛 AI 爱好者。  
3. **15 秒演示**只讲痛点 → 点选 → 确认范围 → 文件；不讲模型与架构。  
4. **配方公开分享与 Recipe 市场后置**；先陪跑、先团队内复跑。  
5. 与计费文档一致：卖**完成任务**，不卖 token；免费须能完整下载一次结果（见 `MODEL.md`）。

---

## 2. 单元经济（内部测算原则）

> 数字为规划假设，需用真实成本与转化校准；**以 `MODEL.md` 为准**。

| 原则 | 说明 |
|------|------|
| 计价 | 任务额度 / 套餐 / 团队池为主；最低付费包可用「任务包」而非抽象币 |
| 毛利 | 软件业务毛利；**不是**上游成本 ×1.1 的转售模型 |
| COGS | 智能调用 + 支付费率 + 失败重试 + 支持预留；靠「样例理解 + 批量程序化」压单位成本 |
| 免费 | 完整可下载任务 + 项数/演示站限流；**不要**在首次价值时刻用过紧美元额度掐断 |
| 裂变佣金 | 可选后期；早期不依赖 Recipe 联盟把 K-factor 当作计划前提 |

**示意（非承诺）：** 若 100 人各购买一个入门任务包，在支付费率与合理 COGS 之后，须仍有空间覆盖早期获客与支持。具体单价与倍率在定价实验中定，**禁止**再维护「1.1x 与 4–5x 两套互相打架的基线」。

## 3. 证据冲刺期：任务验证计划（主循环）

在大规模漏斗之前，先跑通：

1. 找到 **10–20** 名真实运营 / 助理 / 采购相关岗位。  
2. 观察其一天中的浏览器重复劳动（频率、规模、异常、交付格式）。  
3. 只钉死**一个**闭环（默认：本页同类商品整理 + 主图打包；备选：名单/目录进表）。  
4. **创始人陪跑**完成首次真实页面任务。  
5. 一周后看是否**主动再次使用**。  
6. 记录：是否愿付费或明确付费意向、省时感受、失败类型是否可工程化收敛。  

过关 / 止损线见 [`../STRATEGY.md`](../STRATEGY.md) 第 8 节——GTM 成功定义对齐那里，而不是「安装量好看」。

## 4. 早期渠道排序（垂直优先）

| 优先级 | 渠道 | 做什么 |
|--------|------|--------|
| 1 | **垂直社群与服务商** | 跨境电商、运营、采购、独立站、代运营；进群陪跑与案例 |
| 2 | **一对一演示** | 用客户**自己的**页面和交付格式，不秀万能 Demo 站 alone |
| 3 | **中文短视频 / Bilibili / 小红书** | 「手工 40 分钟 vs 几分钟拿文件」；导向**垂直 Landing**，不导向泛 AI 话题流 |
| 4 | **模板与培训合作** | 运营培训师、服务商、行业 KOL（先共创成功任务，再谈分发） |
| 5 | 应用商店搜索与评价 | 文案窄承诺，与定位一致 |
| 6 | Product Hunt / X Build in Public | **品牌曝光**，不是主转化模型；注意反馈人群 ≠ 目标岗位 |

**不要**用「PH 很酷」推断目标市场成立。

## 5. 15 秒 Demo 脚本（标准资产）

```text
0–3 秒：用户反复复制标题、价格、保存图片（痛点字幕：别再这样干了）
3–6 秒：点一个商品卡，说「整理本页同类商品」
6–9 秒：显示「找到约 36 项，字段如下」，用户确认
9–13 秒：表格预览 + 图片包清单
13–15 秒：下载两个文件；字幕「指到哪里，做到哪里」
```

**禁止出镜：** 模型选择、系统提示、Agent 长思考、代码、工具 JSON、架构图、密钥配置。

同一结构可改成「名单整理进表」备选楔子。

## 6. 种子用户漏斗（在任务验证之后）

当封闭测试出现重复使用与付费信号后，再放大：

1. **触达：** 垂直内容 / 社群 / 服务商转介 → 落地页（单任务承诺）。  
2. **安装：** 低摩擦；权限与文案与窄承诺一致（不写全能）。  
3. **登录：** 若需要防刷，说明「额度与同步」；接受合理掉量。  
4. **Wow：** 免费路径完成**一次完整可下载**任务；输出差则直接流失——默认示例与演示页必须打磨。  
5. **付费：** 用户见过文件后再引导任务包 / 月套餐；文案讲「继续处理更多项 / 更高频」，不讲 token。  

量级直觉（假设）：要支撑早期付费样本，需要足够多的**合格岗位安装**，而非泛流量安装；具体转化率以实测为准。

## 7. 配方、分享与「护城河」话术

| 阶段 | 做什么 | 不做什么 |
|------|--------|----------|
| 现在 | 成功两次后提示「记住这次做法」；团队内复跑；成功率与失败回滚意识 | 公开 Recipe 市场当主增长 |
| 稍后 | 管理员发布、版本、同站同任务稳定后再外部分享 | 把脆弱提示词包装成「网络效应已建立」 |
| 更后 | 在跨用户、跨页面变体仍可接受时，再试分享链接与合作佣金 | 用联盟填补产品不可靠 |

对外可说「越用越顺、团队可复用成功做法」；**不要**在 GTM 早期把 Recipe 市场写成已验证护城河。

---

## 8. 与竞争话术

- 承认通用浏览器能力会被大厂做宽。  
- 我们的切口是：**岗位重复劳动 + 指向授权 + 可确认范围 + 可核对文件**。  
- 演示与文案始终落在具体交付，不落在「更强 Agent」。
